AMS Console

Four checkpoints between a ticket and an answer

Where the model is limited, and where a person decides

✓

1 · Before the model

Mask personal data

  • Names, emails, phones, IDs, bank and card numbers become placeholders
  • The model sees placeholders only
  • Real values are put back locally

HowMicrosoft Presidio, plus the team’s own list of terms

✓

2 · Around the model

Limit the model

  • Rules decide first. The model is asked once, for the rest
  • A finding counts only with an exact quote from the ticket
  • A kill switch turns the model off

HowRules run in code · exact-text match on quotes · an admin setting

✓

3 · After the model

A person decides

  • Engineers accept, edit or reject each recommendation
  • A lead approves P1 and P2 closures
  • An expert reviews articles before publishing

HowReview screens in the console, shown by role

✓

4 · On record

Keep the record

  • Each agent’s verdict and reason, next to the engineer’s decision
  • Every settings change, with who and when
  • Sign-in, three roles and a role check on every route

HowA database record per agent run and per change · password or Atlassian sign-in

Assigns ticketsGroups incidentsSends stakeholder updates on open P1 and P2 incidents · own off switch
