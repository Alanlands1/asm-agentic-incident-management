The challenge we set out to solve

Four operational challenges that most affect incident outcomes

Our review narrowed the focus to four recurring gaps: scattered knowledge, data quality, inconsistent triage and troubleshooting, and communication and reporting. The console is built to steady these four areas on every ticket.

AMS Console

Five intelligent agents. One connected system.

Specialised agents that hand their results to each other

A1

Data Quality

Key capability: checks the ticket before any work starts

Checks every ticket against rules the team writes. It flags an incomplete ticket with the reason and drafts the email asking the requester for what is missing.

A2

Triage

Key capability: priority from the rulebook, not the requester

Reads the ticket, applies the business rulebook and sets the priority and application. A lowered P1 or a large change is flagged for an engineer’s review. The model reports regulatory, financial and system impact beside it.

A3

Resolution

Key capability: a suggested fix grounded in sources

Searches the runbooks and similar closed tickets by meaning and by keyword, then proposes steps and shows where each came from.

A4

Closure Quality

Key capability: complete, consistent closure notes

Scores the closure note for cause, action and check. It asks the engineer short questions and drafts the note with the gaps marked.

A5

Knowledge Builder

Key capability: turns good fixes into knowledge

Matches each resolved ticket to an article, drafts a new article where none covers it, and suggests a problem record for repeat issues.

Lead desk

Key value: the right engineer, without a round of messages

Assignment with a suggestion that knows shift hours, leave and open load. Review queue for P1 and P2 closures.

Incidents and SLA

Key value: one incident, not twenty tickets

A burst of related tickets is grouped into one incident, with the SLA clock and drafted stakeholder updates.

AI assistant

Key value: context-aware help on the ticket

A chat on the ticket to work out a fix, reading team notes, similar closed tickets and the knowledge base.

Console

Next.js. One console for the engineer, the lead and the admin.

Backend

FastAPI. Masks personal data with Presidio before a ticket is saved, then runs the five agents: rules first, then the model.

Registry

Prompts, rules, SLA and masking settings kept in files. An admin can override them while the system runs.

Model

Model gateway

Every model call goes through one function. It masks personal data again and puts the real values back in the answer.

Outage breaker

A run stops after five failed calls in a row when the model is unavailable.

Claude API

The model. It only ever sees masked text.

AMS Console

AI with controls at every layer

Governance · Every layer has a control designed in from day one

Data

Personal data is masked before a ticket is saved, and again before any model call. The model receives placeholders only.

▼

Governance controls

Sign-in, three roles, a role check on every API route, and a history of every settings change.

▼

Trusted AI response

Every finding needs an exact quote from the ticket. A person confirms before anything is sent.

Personal data auto-masking

Names, emails, phones, employee IDs, bank and card numbers become numbered placeholders. Real values are put back locally.

Only what a person sends reaches Jira

The closure note and replies go to Jira when the engineer sends them. The agents’ own comments and labels stay off unless an admin switches them on.

Full record of agent results

Each agent’s verdict and reason is stored with the ticket, next to the engineer’s decision on it.

Human review path

Engineers accept, edit or reject each recommendation. A lead approves P1 and P2 closures. A kill switch turns the model off.
